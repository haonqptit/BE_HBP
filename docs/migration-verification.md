# Migration ↔ schema.sql parity

`docs/schema.sql` is the authority. The EF migrations (`InitialCreate`, `AddLoginLockout`) must
produce a database equivalent to it. This document records how that is checked and which
differences are accepted.

## Automated gate

`tests/HBP.IntegrationTests/SchemaParityTests.cs` runs the migrations against a real
PostgreSQL 16 container (Testcontainers) and asserts the objects EF cannot express on its own
survive: both extensions, the ten `trg_*` triggers, `set_updated_at()` / `normalize_email()`,
the five GIN pg_trgm indexes, and the three lockout columns. It runs as part of `dotnet test`.

## Manual `pg_dump` diff

Run this whenever a Configuration class or an entity changes. It is the most reliable signal
that a mapping drifted away from the DDL.

```bash
dotnet ef migrations script --project src/HBP.Infrastructure --startup-project src/HBP.Api -o artifacts/initialcreate.sql
```

Apply `docs/schema.sql` to one database and `artifacts/initialcreate.sql` to another, then diff:

```bash
pg_dump --schema-only --no-owner --no-privileges -d "$REFERENCE_URL" > artifacts/reference.sql
pg_dump --schema-only --no-owner --no-privileges -d "$MIGRATED_URL" > artifacts/migrated.sql
diff -u artifacts/reference.sql artifacts/migrated.sql
```

Anything the diff reports that is not listed below is a bug in a `Persistence/Configurations`
class. Fix it in the configuration and regenerate the migration — do not paper over it with raw
SQL in `Up()`.

## Raw SQL kept in `Up()`

Three groups genuinely cannot be expressed through the fluent model, and are emitted with
`migrationBuilder.Sql` (each mirrored by a `DROP` in `Down()`):

1. **Functional unique indexes on `admin_users`** — EF creates a plain unique index; it is dropped
   and replaced with `CREATE UNIQUE INDEX … ON admin_users (lower(username))` and the same for
   `lower(email)`.
2. **GIN pg_trgm indexes** — `USING gin (col gin_trgm_ops)` on `booking_requests`
   (`full_name`, `email`, `phone_number`) and `contact_requests` (`full_name`, `email`).
   They are created after the `pg_trgm` extension, which the model declares via
   `HasPostgresExtension`.
3. **Trigger functions and triggers** — `set_updated_at()`, `normalize_email()` and the ten
   `CREATE TRIGGER` statements.

## Accepted differences

| Difference | Why it is accepted |
|---|---|
| `__EFMigrationsHistory` table exists only in the migrated database | EF bookkeeping; not part of the application schema. |
| Constraint and index names generated by EF where `schema.sql` left them implicit | Names differ only where PostgreSQL would have auto-generated them too; the constrained columns and semantics match. |
| Ordering of statements in the dumps | `pg_dump` output order is not semantically meaningful. |
| `admin_users.failed_count` / `first_failed_at` / `locked_until` | Added by `AddLoginLockout` per the agreed lockout design; `docs/schema.sql` predates it. |

The lockout columns are the only intentional divergence from `schema.sql`. If that file is ever
regenerated, it should include them.
